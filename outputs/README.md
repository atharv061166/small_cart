## <a id="overview"></a>📊 Overview

The `outputs/` folder contains pre-computed ML models, features, and recommendation artifacts. These files enable:
- **Fast inference** at runtime without expensive computations
- **API serving** with zero-latency recommendations
- **User-agnostic trending** based on time-of-day and day-of-week context

## <a id="output-files"></a>📁 Output Files

### 1. **train_features.parquet**

**Size**: ~200 MB | **Rows**: ~1.5M (user-product pairs) | **Columns**: 18+

#### 📝 Description
The core feature matrix used for training the LightGBM recommendation model. Contains engineered features computed at the user and user-product interaction level.

#### 🔧 Generated By
- **Source Script**: `notebooks/feature_engineering_trending.ipynb` (or `notebooks/reconstruct_features.py` for older versions)
- **Input Data**: `data/combined_instacart_data.csv`
- **Pipeline**: Raw data → User features + Product features + User-Product interaction features

#### 📋 Feature Columns
- **User-level**: `user_total_orders`, `user_avg_basket_size`, `user_reorder_rate`, `user_avg_days_since_prior`, `user_fav_hour`, `user_fav_dow`
- **Product-level**: `product_total_orders`, `product_unique_users`, `product_reorder_rate`, `product_avg_position`, `aisle_id`, `department_id`
- **Interaction-level**: `up_times_ordered`, `up_reorder_rate`, `up_last_order_number`, `up_first_order_number`, `up_order_recency`, `up_order_freq_ratio`
- **Engineered**: `user_vs_global_affinity`, `product_log_popularity`
- **Target**: `target` (1 = reordered, 0 = not reordered)

#### 📤 Used By
- **Training**: `models/lightgbm_model.py` — Loads features to train the LightGBM classifier
- **Backend**: `backend/recommendation_engine.py` — Loads features to run the live LightGBM inference model for active/hybrid user recommendations

#### 🎯 Purpose
Provides a normalized, memory-efficient feature matrix for fast model training and inference without recomputing statistics from raw data.

### 2. **lgbm_model.txt**

**Size**: ~10 MB

#### 📝 Description
Serialized LightGBM decision tree model trained on `train_features.parquet`. Uses gradient boosting to predict the probability that a user will reorder a given product.

#### 🔧 Generated By
- **Source Script**: `models/lightgbm_model.py` (function: `save_artifacts()`)
- **Training Process**:
  1. Load features from `train_features.parquet`
  2. Split by user (80/20 train/test, then 85/15 train/val)
  3. Tune hyperparameters via GridSearchCV
  4. Train LightGBM classifier with early stopping
  5. Evaluate on held-out test set
  6. Serialize using `model.save_model()`

#### 🏋️ Model Details
- **Algorithm**: LightGBM (Gradient Boosting)
- **Objective**: Binary classification (reorder vs. not)
- **Early Stopping**: Monitors validation AUC
- **Hyperparameters**: Tuned via GridSearchCV (learning rate, num_leaves, min_data_in_leaf)

#### 📤 Used By
- **Backend**: `backend/recommendation_engine.py` — Loaded by the recommendation engine via `lgb.Booster` to score products in real-time for active users (21+ orders) and hybrid users (10-20 orders)

#### 🎯 Purpose
Powers the "LightGBM" recommendation engine for users with sufficient order history. Captures learned patterns about user-product affinity.

---

### 3. **lgbm_feature_cols.pkl**

**Size**: <1 KB

#### 📝 Description
Pickle file storing the ordered list of feature column names used during LightGBM training. Ensures consistent feature ordering during inference.

#### 🔧 Generated By
- **Source Script**: `models/lightgbm_model.py` (function: `save_artifacts()`)
- **Creation**: After feature engineering, extracted as `feature_cols = [... 18 features ...]` and pickled

#### 📤 Used By
- **Backend**: `backend/recommendation_engine.py` — Unpickles to reconstruct feature vectors and align columns in the correct order for real-time model scoring

#### 🎯 Purpose
Prevents feature column mismatch between training and inference (a common ML pitfall). Guarantees reproducibility.

---

### 4. **lgbm_threshold.json**

**Size**: <1 KB

#### 📝 Description
JSON file containing the optimal decision threshold (probability threshold) determined during model evaluation on the validation set.

#### 🔧 Generated By
- **Source Script**: `models/lightgbm_model.py` (function: `save_artifacts()`)
- **Creation**: During threshold tuning, evaluates F1-score across validation predictions from 0.20 to 0.65 (steps of 0.01) to find the threshold yielding the highest F1-score.

#### 📤 Used By
- **Backend**: `backend/recommendation_engine.py` (optional: to align classification threshold for active users)

#### 🎯 Purpose
Stores the tuned probability classification threshold to ensure recommendations map to the highest possible F1-score under the trained model.

---

### 5. **mba_rules.pkl**

**Size**: ~5 MB

#### 📝 Description
Serialized association rules from FP-Growth algorithm. Represents frequent item patterns: "customers who buy X also buy Y" with confidence and lift metrics.

#### 🔧 Generated By
- **Source Script**: `models/market_basket.py` (function: `save_artifacts()`)
- **Pipeline**:
  1. Load order-product interactions from `order_products.parquet`
  2. Build transaction baskets (samples for memory efficiency)
  3. One-hot encode products (sparse matrix)
  4. Run FP-Growth with min_support=0.01
  5. Generate association rules (min_confidence=0.1, min_lift=1.5)
  6. Filter out popularity bias
  7. Pickle rules dictionary

#### 📊 Rule Metrics
- **Support**: Frequency of the rule in all transactions
- **Confidence**: P(consequent | antecedent)
- **Lift**: How much more likely the consequent is given the antecedent

#### 📤 Used By
- **Backend**: `backend/recommendation_engine.py` → `_fpgrowth_recommend()` — Used by the recommendation engine to generate association-based recommendations for new users (0-9 orders) and hybrid users (10-20 orders)

#### 🎯 Purpose
Captures "frequently bought together" patterns without ML training. Fast and interpretable for real-time recommendations to users with limited order history.

### 8. **trending_scores.parquet**

**Size**: ~22 MB | **Rows**: ~796,480

#### 📝 Description
The core trending product scoring table. Every row represents a product's trend score in a specific context (day-of-week + time-of-day bucket).

#### 🔧 Generated By
- **Source Script**: `notebooks/build_trending_data.py` (or `notebooks/feature_engineering_trending.ipynb`)
- **Pipeline**:
  1. Load `data/combined_instacart_data.csv` in chunks
  2. Compute for each product × context (day_of_week × time_bucket):
     - **Purchase frequency**: How many times ordered in that context
     - **Reorder rate**: % of times the product was reordered
     - **Weighted score**: `0.5 × normalized_frequency + 0.3 × reorder_rate + 0.2 × contextual_frequency`
  3. Normalize scores per context to [0, 1] scale

#### 📋 Columns
- `product_name`, `department`, `aisle` — Product metadata
- `order_dow` (0-6) — Day of week (0=Saturday, 6=Friday)
- `time_bucket` — "morning" (5-11), "afternoon" (12-17), "night" (18-4)
- `purchase_count` — Raw order frequency
- `reorder_rate` — % of orders that reordered
- `normalized_purchase_frequency` — Scaled to [0, 1]
- `contextual_frequency` — Fraction of all purchases in that context
- `weighted_score` — Final ranking score

#### 📤 Used By
- **Dashboard**: Frontend `AdminDashboardPage.jsx` → Loads CSV or parquet for visualization
- **Analysis**: Data scientists for trend investigation
- **Reference**: Backup for trending lookup (see below)

#### 🎯 Purpose
Enables exploratory analysis and debugging. Full table view of all trending computations before aggregation into the fast lookup dictionary.

### 10. **trending_lookup.pkl**

**Size**: <1 MB | **Entries**: 21 contexts

#### 📝 Description
Pre-computed, **heavily optimized** dictionary mapping (day_of_week, time_bucket) contexts to the top-20 products in that context. This is the **fastest lookup** for trending recommendations.

#### 🔧 Generated By
- **Source Script**: `notebooks/build_trending_data.py` (function: `build_lookup_dict()`)
- **Structure**:
  ```python
  {
    ("Saturday", "morning"): [
      {"product_id": 123, "product_name": "Organic Milk", "score": 0.95, ...},
      {"product_id": 456, "product_name": "Eggs", "score": 0.92, ...},
      ...  # up to 20 products
    ],
    ("Saturday", "afternoon"): [...],
    ...  # 3 time buckets × 7 days = 21 contexts
  }
  ```

#### 📤 Used By
- **Backend**: `backend/trending_engine.py` → `_load_trending_data()` — Loads into memory on startup
- **API**: `/trending` endpoint — Returns top products for current context in **O(1)** time
- **Homepage**: Frontend displays trending products

#### 🎯 Purpose
**Zero-latency trending**: Pre-aggregated top-20 per context enables instant API responses. No filtering, sorting, or computation at request time.

## <a id="runtime-usage"></a>🚀 Runtime Usage

### Backend API (`backend/main.py`)
1. **Startup**: Calls `recommendation_engine._load_models()` + `trending_engine._load_trending_data()`
   - Loads `lgbm_model.txt`, `lgbm_feature_cols.pkl`, `mba_rules.pkl`, `product_names.parquet`
   - Loads `trending_lookup.pkl`, `trending_departments.parquet`
2. **Request `/api/recommendations` (POST)**:
   - Determines user segment (0-9, 10-20, 21+ orders)
   - Uses appropriate engine (FP-Growth, Hybrid, LightGBM)
   - Returns product names from `product_names.parquet`
3. **Request `/api/trending`**:
   - Gets current (day_of_week, time_bucket)
   - Looks up in `trending_lookup.pkl` — O(1) response

### Recommendation Serving
- Recommendations are served dynamically by the FastAPI backend in `backend/recommendation_engine.py`, which loads the model files (`lgbm_model.txt`, `lgbm_feature_cols.pkl`, `mba_rules.pkl`, `product_names.parquet`) on startup and scores products in real-time.

## <a id="regeneration-workflow"></a>🔄 Regeneration Workflow

If you need to **update any outputs** (e.g., after collecting new data):

### Step 1: Regenerate Features
```bash
python notebooks/reconstruct_features.py
# or run feature_engineering.ipynb
# Outputs: train_features.parquet, product_names.parquet, order_products.parquet
```

### Step 2: Train Models
```bash
# LightGBM
python models/lightgbm_model.py
# Outputs: lgbm_model.txt, lgbm_feature_cols.pkl, lgbm_threshold.json

# Market Basket (FP-Growth)
python models/market_basket.py
# Outputs: mba_rules.pkl
```

### Step 3: Generate Trending Artifacts
```bash
python notebooks/build_trending_data.py
# Outputs: trending_scores.parquet, trending_scores.csv, trending_lookup.pkl, trending_departments.parquet
```

### Step 4: Restart Backend
```bash
# The API will reload all artifacts on startup
python backend/main.py
```

## <a id="troubleshooting"></a>⚠️ Troubleshooting

### Model scores not updating
→ Regenerate: `python models/lightgbm_model.py`

### Trending products stale
→ Regenerate: `python notebooks/build_trending_data.py`

### Backend fails to start
→ Check: All files exist in `outputs/` with non-zero size
→ Try: Delete `.pkl` files and restart (will reconstruct)

### Feature column mismatch error
→ Ensure `lgbm_feature_cols.pkl` matches your `train_features.parquet` schema
→ Regenerate both via `notebooks/feature_engineering.ipynb` → `models/lightgbm_model.py`
